## Deferred / Watch

- ⚠️ **`Media::fileIsShared()` has a benign concurrent-delete race — flagged 2026-09-01, deliberately not fixed.** The guard is a read (`exists()`) followed by a delete, with no lock between them, so two simultaneous deletes of rows sharing one `disk`+`path` can each see the other still present and each skip the disk delete — leaving a **leaked file** with no rows pointing at it. It can never lose a file a live row still needs, which is the failure the guard exists to prevent; the residue is wasted bytes. Sequential deletes — the only path an admin actually produces — resolve correctly, the last row taking the file with it. Not fortified because the cost is disk space, the trigger needs two concurrent deletes of path-sharing rows, and the alternatives (a lock, or a sweeper) both buy more machinery than the problem. **Revisit if** shared paths stop being an artifact of the save-churn replacement case and become a normal state (e.g. deliberate media deduplication), at which point a periodic orphan-file sweep is the shape — not a lock.

- 💭 **Convert `InitiatePayment` to a published FlowChain** — `InitiatePayment`'s 5 internal steps (gateway resolve → payment record create → customer ID resolve → session create → gateway-reference write-back) would let consumers insert fraud check pre-session, analytics ping post-session, custom customer-resolution branch, etc. without forking the action. **Blocked on sub-chain machinery** (`->chain()` builder method + `FlowChainBridge` interface, child step results nest into parent's `FlowChainResult`) — see FlowChain README §Child Chains for Option B/C design. AddToCartChain (v0.22.0) is the first published chain and proves the basic `PublishableFlowChain` path works; InitiatePayment specifically needs the nested-chain primitive that's still unbuilt. Narrower than "convert all of Payment": `RefundPayment` shouldn't be split (lockForUpdate + intentional gateway-call-before-DB-write ordering doesn't fragment cleanly), `ProcessPaymentWebhook` doesn't fit either (early-return-null successful no-ops, no parent chain to nest into). Trigger to un-defer: a real consumer extension request, OR new payment surface area (subscription renewals, 3DS retry, manual charges) that adds steps the current single action can't cleanly accommodate.

- 💭 **`AttachTag` / `AttachCategory` are not idempotent — and the premise here was wrong** (re-checked 2026-08-25). The note used to say a second attach "creates a duplicate pivot row". It cannot: `taggables` and `categorizables` both carry a UNIQUE index (since the 2026-04-08 extraction), so the second attach **throws a raw `QueryException`** — a 500 for any caller that doesn't pre-check. **There is also a later, opposite ruling on file:** `AttachDetachCategoryTest` (2026-05-29, `93b7db9`) pins the throw as the contract and says "if the consumer wants idempotency they must wrap with `syncWithoutDetaching` or similar at the call site". So this needs Jelte's pick, not a build slot — **it was implemented and reverted 2026-08-25** for exactly that reason.
  - Evidence for moving idempotency into the action: the call-site policy has already produced one hand-rolled bypass and one unguarded call. `in-other-worlds`' `AttachTagToContent` agent tool pre-checks `$content->tags->contains(...)` and then calls `$content->tags()->attach()` **directly, skipping the action** — so an agent-attached tag dispatches **no `TagAttached`** and never reaches the audit log. `CreateContentTranslation` calls `AttachCategory` with no pre-check at all, so translating a sibling into a category it already has 500s.
  - Fix shape if the ruling flips: `syncWithoutDetaching([$tag->getKey()])` in both actions, dispatch the event only when `$changes['attached'] !== []` (load-bearing for `AttachCategory` — `MaintainCategoryCounts` would otherwise re-increment every ancestor for a membership that already existed). The two `*_violates_the_unique_pivot_constraint` tests get retargeted onto a direct-`attach()` call so the DB net stays pinned. Consumer half: delete IOW's bypass and route the agent tool back through the action.
